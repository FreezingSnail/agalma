Upgrade, activation, rollback (procedure)

Persisted contract versions live in kernel_meta (exec_def_version, kernel_version) and the physical ledger schema version is checked (KernelEngine::EXPECTED_LEDGER_SCHEMA_VERSION). An unknown exec_def version or a mismatched schema parks every execution rather than guessing.

Candidate check (reducer-only)

agalma_kernel::check_candidate(&ledger, migrations) replays every execution from execution_events and compares the derived state with the executions projection. It writes nothing and runs no external effect (verified by an empty effect journal). It reports per-execution Compatible, NeedsMigration, or Parks.

Explicit migration

MigrationRegistry holds explicit Migrations. KernelEngine::open_with_migrations applies a resolved stored → exec_def/v1 migration before reconstructing work, through LedgerApi only. Incompatible state with no migration parks. VersionLabelMigration is the safe case (a byte-compatible relabel); it records a durable migration:<from> marker. Real history-rewriting migrations register additional Migration implementations.

State export / import (compatible replacement)

LedgerApi::export_state / import_state produce/consume a canonical JSON StateSnapshot (format header agalma-state/v1; schema_version; exec_def_version; kernel_version; kill latch; every kernel_meta row incl. worker records; lease generations; projection; history; receipts; dispatch intents incl. their consumed flag; timers; directives; bindings). Import refuses a format/schema mismatch atomically (nothing partially applied) and is canonical: export → import → export is byte-identical. Canonical ids, receipts, and pending work survive; consumer APIs are unchanged.

Staged activation (staged_activate)

  1. Set latch — physical conductor latch and the durable per-execution KillLatch command (blocks new and recovered dispatch).
  2. Settle/reconcile in-flight — probe every pending operation through its pinned binding; a present effect is completed (never repeated), an absent effect is left pending for the post-activation resume, an ambiguous effect aborts activation with the latch still set.
  3. Stage candidate — upsert the candidate as Staged after the bind gate (required_capabilities ⊆ capabilities).
  4. Swap binding (S0d rebind rules) — previous active → Draining (retained for pinned operations), candidate → Active.
  5. Schema check — refuse on a mismatched ledger schema.
  6. Clear latch — resume. Events are recorded in kernel_meta::activation_evidence:<component_api>.

Rollback (rollback)

Settle in-flight, mark the candidate Retired (kept for reconciliation), reactivate the seed binding, keep every pending operation pinned to the binding it started under, record rollback_evidence:<component_api>, resume. The seed's recovery path stays available.

Restore (restore)

Check schema compatibility first, then reconcile ledger, bd, Git, processes through the RestoreReconciler seam before any dispatch, with the latch set. An ambiguous domain parks the execution and leaves the latch set (nothing dispatches on stale/ambiguous state); a clean reconcile clears the latch and resumes. Evidence is recorded in kernel_meta::restore_evidence:<execution>.

Deviations and open items

  • Consumer API unchanged. export_state/import_state were added to the LedgerApi contract (additive) and implemented for SqliteLedger; the ExecutionApi seed executor and conductor are untouched and all their tests pass. The kernel carries its own EXPECTED_LEDGER_SCHEMA_VERSION = 3 so it still depends only on agalma-contracts.
  • Restore seam. RestoreReconciler is a contract-level seam; B0.6 tests a deterministic fake. Wiring the live conductor's bd/Git/process reconciliation into it is integration (out of the B0 kernel crate), tracked as a follow-up.
  • Activation not yet switched on. The staged-activation/rollback mechanics are implemented and tested, but the conductor still runs the seed binding; performing the controlled-restart rebind in the live conductor is the activation step owned by the accepted conductor.
  • Migration coverage. Only VersionLabelMigration ships (a compatible relabel, which is what the current exec_def/v1 needs). A future definition change adds a payload-rewriting Migration; the registry already supports it.
  • Kernel schema-mismatch park is exercised via the candidate report and the snapshot schema refusal; a live ledger can only reach a non-3 schema through a future migration (the ledger refuses commits under a mismatch).
  • Resource limits are derived from a debug build on one host and should be re-measured in release at promotion; the harness is re-runnable and deterministic in shape.
