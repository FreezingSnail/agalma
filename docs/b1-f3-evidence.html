3. Default-flip decision

Deferred, with the live gate satisfied. The live OpenCode process route is proven (§2), so the only thing standing between B1-F3 and the flip is a downstream integration defect that the flip exposes. Flipping HarnessTransport::from_env to default Process turns the deterministic scripted reference path (phases::run_reference) into a process spawn, and the reference server socket it opens is <state_dir>/harness-ref-<attempt>.sock. In the test scratch dirs (and any long production state dir) that path exceeds SUN_LEN (~104 bytes), so the server cannot bind:

agalma-harness-reference-server: serve …/state/harness-ref-1.sock:
  path must be shorter than SUN_LEN
test …rebind… FAILED: step: KnownFailure("server did not announce READY within 20s")

With the default flip applied, cargo test --offline -p agalma-conductor --test rebind went 4 failed / 1 passed; with the default unchanged it is green. This is a latent path-length defect on the reference process boundary, not a fault in the OpenCode route the smoke exercised (the smoke's state dir was short enough that <state>/harness-build-1.sock bound). Because the mandated gate cannot pass with the flip, the default is left in-process and the flip is deferred to a follow-up that shortens the reference socket path (a short per-run socket dir, as the harness_process boundary tests already do) — the HarnessTransport enum, the process selection, and the single env-default site are unchanged from B1.

6.2 Alias mechanics

crate::phases::bounded_socket_path(state_dir, name) returns the direct <state_dir>/<name> when as_os_str().len() < SUN_LEN_LIMIT (104), else <temp_dir>/agalma-sock/<8hex-state-hash>/<name>. The bounded parent is a symlink to the state dir, so the socket file still lands in state_dir — components.rs liveness/watch/GC (state_dir.join("<name>.sock").exists() and the harness*.sock glob) stay valid. Alias construction failure falls back to the direct path (unchanged semantics; the caller reports the bind error). harness_socket_path delegates: InProcess → direct, Process → bounded_socket_path. Unit tests: process_harness_socket_path_is_bounded_for_long_state_dirs (long dir canonicalize proof, short dir direct, in-process direct) and bounded_socket_path_reuses_alias_and_bounds_long_dirs (alias reuse/stable base).

6.3 Required follow-on fixes (agalma-ipc)

Flipping the defaults exposed two latent defects on the Connect client path that the in-process defaults had masked (the same class agalma-ud1 fixed for the harness/sandbox clients):

  1. Nested-runtime connect/call. ledger/workspace/taskqueue/execution connect_wire and workspace/taskqueue call used a raw Runtime::block_on from inside the conductor's Tokio runtime → "Cannot start a runtime from within a runtime". Routed through the existing block_on_nested helper (mirrors harness/sandbox clients).
  2. Blocking runtime drop. ConnectBackend dropped a multithread Runtime inside the async conductor → "Cannot drop a runtime in a context where blocking is not allowed". Added the agalma-ud1 runtime: Option<Runtime> + shutdown_background() Drop to the four clients.
  3. Orphaned supervised servers on conductor SIGKILL. A supervised server outlived a hard-killed conductor and kept its state-dir lock, so a restart (recovery case 1/4) could not rebind. spawn_supervised now spawns the server with a piped stdin held open for the server's lifetime and sets AGALMA_SERVER_PARENT_DEATH_STDIN; agalma_ipc::serve_wire watches stdin for EOF and exits, so a server never outlives its supervisor. (Also fixed the signal-handler wire: LedgerClient::connect now uses the env-selected wire — Connect default — matching the server, so the kill latch persists under the flipped default.)
