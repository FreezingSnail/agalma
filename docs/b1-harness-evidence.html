Default transport decision

HarnessTransport::from_env() reads AGALMA_HARNESS_TRANSPORT (in-process default, process optional). The default is left in-process.

Deviation (factual, per D5): the build/verify phase code is unchanged, so the phase path still constructs harnesses in-process and does not consult the transport env var. Flipping the default to process would therefore be inert in this bead and cannot be validated by the suite. The process transport is instead proven directly by the dedicated boundary tests above, which pass in the full suite. Wiring the build activity to the transport factory is deferred so "consumer logic unchanged" (D5) holds; it is the natural B1.3 follow-on when the sandbox boundary lands and the server socket layout is finalized.

Deviations and design corrections (noted, not applied to docs/b1-extraction.md)

  1. Architecture-test carve-out for the harness server's in-process sandbox. D6 forbids impl→impl normal dependencies, but D2's derived requirement says an already-extracted server hosts a not-yet-extracted dependency in-process until that dependency is extracted (the harness server uses the sandbox client only after B1.3). These conflict for the harness server, which the bead explicitly requires to construct OpenCodeHarness::new(Box::new(SeatbeltSandbox::new()), config). tests/architecture.rs therefore gains one sanctioned, documented edge (agalma-harness-opencode -> agalma-sandbox) in both the Cargo.toml and source-token checks, removed when B1.3 lands. This is a test change under the allowed crates/agalma-conductor/**; no contract or phase logic changed.
  1. OpenCode server configuration. The server assembles its config from environment (AGALMA_HARNESS_ROOT, AGALMA_HARNESS_PROFILE_PATH, AGALMA_HARNESS_PROXY_URL, AGALMA_HARNESS_PAID_PROXY, AGALMA_MODEL) via the shared build_config constructor that the conductor's build/verifier paths now also call (removing the duplicated provider-override logic). The OpenCode process path is not exercised end-to-end in this bead (it needs a live opencode install and the B1.3 sandbox boundary); only the reference transport is driven by tests. The server runs its serial serve loop inside a multithread Tokio runtime because sandbox-backed methods require a reactor.
  1. Unix socket path length. Component sockets live directly under short target/test-runs/hp-<pid>-<n>/ run dirs in tests to stay within SUN_LEN (~104 bytes). The supervisor already creates the socket's parent directory.
  1. Cargo.lock. Modified only to add the new intra-workspace dependency edges (agalma-ipc for the conductor, reference, and OpenCode crates). No new external crate was added; the lockfile delta is a mechanical consequence of the Cargo.toml changes above.

IPCX.2 — harness boundary on the Connect transport

Bead: agalma-ebg.3. Design: docs/ipc-connect-design.md (D1–D7). Foundation: agalma-ebg.2 (ipc.proto, Connect stack + pins, UDS accept loop, client core, Connect-level conformance harness). HEAD at start: 79e3b42.

Goal: move the already-extracted HarnessApi process boundary onto the Connect transport (IPCX D7, boundary #1) without changing the envelope semantics or any consumer logic, and prove it with the B1 recipe — dual-binding parity, staged rebind, rollback, IPC conformance — extended to the Connect wire. This is the per-boundary evidence D4 names (docs/ipcx-<boundary>-evidence.md); it is folded into this file so the harness boundary's B1 and IPCX evidence stay together.

What migrated

The typed harness client and its method-registration helper stay the entry points; only the byte transport under them changed.

  • The harness process wire defaults to Connect (harness_wire()); a parity run sets AGALMA_IPC_WIRE=framed to compare the two against the same scenario. The selected wire is exported to the child in the same variable, so the server serves the matching transport. Both wires announce the identical READY {json} line, so the supervisor handshake and bind gate are unchanged.
  • Envelope semantics are preserved verbatim on both wires: v/id/method/ params_json; duplicate-id receipt replay; UnknownOutcome/contract errors in-band; version refusal; unknown-method UnsupportedCapability. The Connect path reuses Server::dispatch, so no envelope code was forked.
  • Process-transport test call sites were adapted to the new ProcessBinding::spawn(.., wire, ..) signature with no consumer-logic change: crates/agalma-conductor/tests/harness_process.rs (parity/rebind) and crates/agalma-conductor/tests/designer_payload.rs (real OpenCode server, Wire::Connect).
  • No new dependency. connectrpc/buffa stay confined to agalma-ipc (architecture test unchanged and green); no Cargo.toml/Cargo.lock change.

New interfaces

  • agalma_ipc: connect::{Wire, WIRE_ENV, serve_wire}, ConnectClient::call_typed; harness_client::HarnessClient::connect_wire (framed connect/from_client retained); harness_server::serve_harness.
  • agalma-harness-reference: serve_wire (framed serve retained).
  • agalma_conductor::harness_process: harness_wire, ProcessBinding::wire, ProcessBinding::spawn(.., wire, ..).

Deviations and notes

  1. The IPCX design D4 names a per-boundary docs/ipcx-<boundary>-evidence.md; this bead's scope extends the existing B1 harness evidence instead, keeping the framed and Connect proofs side by side.
  2. The harness process wire defaults to Connect. The process transport itself is still only exercised by the boundary tests (the phase path constructs harnesses in-process, unchanged since B1.2), so the default flip changes no production path; AGALMA_IPC_WIRE=framed restores the framed wire for parity.
  3. serve_wire installs a multithread Tokio runtime for both wires so server-hosted implementations that need a reactor (the OpenCode harness) keep working; the framed branch runs the serial accept loop under block_on, as it did before.
