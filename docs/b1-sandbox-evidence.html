B1.3 — sandbox extraction evidence

Bead: agalma-0ht.4. Design: docs/b1-extraction.md (D1–D5, D7). Depends on agalma-0ht.3 (B1.2 harness extraction). HEAD at start: dfa6142.

Goal: move SandboxApi behind a process (Unix-socket) boundary without changing any contract schema or consumer (phase) logic, and prove replacement through the declared API with dual-binding parity, staged rebind, rollback, and IPC conformance. As a derived requirement (D2), the already-extracted OpenCode harness server switches from embedding agalma-sandbox in-process to driving the extracted sandbox client.

Default transport decision

HarnessTransport::from_env() reads AGALMA_HARNESS_TRANSPORT (in-process default, process optional). The default remains in-process.

Deviation #2 from B1.2 is resolved: the build/verify construction sites now consult the transport factory. run_live/run_verifier_session build the live harness through harness_process::open_opencode_harness(OpenCodeHarnessInit { transport, .. }), and run_reference builds the reference harness through open_reference_harness(kind, transport, ..). With the default the phase path is byte-for-byte behaviourally unchanged; with AGALMA_HARNESS_TRANSPORT=process the phase path spawns the selected component server (ProcessBinding / LiveHarness::Process). Phase dispatch, ordering, recovery, and activity bodies are unchanged; only the harness construction sites and the shared drive helper's parameter type (&mut LiveHarness / &mut dyn HarnessApi) changed.

The OpenCode process branch is constructed but not exercised against a live opencode install offline (it needs a real install and provider egress). The reference transport is proven end-to-end offline by tests/harness_process.rs; the sandbox transport is proven by tests/sandbox_process.rs.

Conductor sandbox supervision and injection

SandboxProcess spawns agalma-sandbox-server --socket <state_dir>/sandbox.sock as a process-group leader, waits for READY, and connects SandboxClients. It reuses the exact spawn_supervised/stop_supervised helpers extracted from harness_process (one supervision implementation for every boundary). SandboxSource starts the server lazily on first use and keeps it alive for the phase activities.

Injection points (where a Box<dyn SandboxApi> was constructed or passed):

  • phases.rs build (run_live) and verifier (run_verifier_session) harness construction: the in-process branch injects Box::new(SandboxClient) connected to the supervised server; the process branch passes the sandbox socket to the OpenCode server via AGALMA_SANDBOX_SOCKET.
  • agalma-harness-opencode/src/server.rs: the server connects a SandboxClient from AGALMA_SANDBOX_SOCKET and injects it into OpenCodeHarness::new.

composition.rs/work.rs construct the phase activities (not a Box<dyn SandboxApi>), so they are unchanged; activities_with_mode builds the SandboxSource from PhaseDeps::state_dir.

Component-server confinement (D2)

Per the B1 design clarification (commit 717a70f), component servers are trusted code: the conductor supervises them (spawn as group leader, READY gate, SIGTERM/SIGKILL evidence) but does not OS-confine them. OS confinement (SandboxApi + PRODUCT_PROFILE) is reserved for candidate or untrusted implementations and the harness's confined opencode serve child, which the sandbox server launches. The harness child's loopback allowance is unchanged: provider egress tunnels through the parent-owned loopback proxy (provider_proxy) and the S0b profile permits that loopback path. No new profile work was required for component servers, because they are not confined.

Deviations and design corrections (noted, not applied to docs/b1-extraction.md)

  1. Kernel seam is wiring-only; no code change. KernelEngine::with_sandbox already takes Box<dyn SandboxApi>, and there is no production construction site in the conductor today (only kernel tests inject a fake). SandboxClient satisfies the seam; agalma-ipc asserts SandboxClient: SandboxApi + Send at compile time (sandbox_client::tests::sandbox_client_is_a_send_sandbox_api). No agalma-kernel/** file changed.
  2. Sandbox has no Describe/binding record. SandboxApi is a stateless three-method contract, so the "staged rebind" is a supervised-server swap with the in-flight child pinned to its launching server, rather than a BindingRecord swap (the harness boundary, which has Describe, keeps the record-based rebind in tests/harness_process.rs).
  3. One-shot SeatbeltSandbox::run stays in-process. run is an inherent one-shot used by the conductor's verify phase (exit code as verdict); it is not part of SandboxApi, so it is out of scope for this boundary. Likewise build_probe reconciles survivors through the in-process backend, because boot recovery probes run before any component server is supervised.
  4. Unix socket path length. Sandbox and harness sockets live directly under the run state dir (sandbox.sock, harness-<phase>-<attempt>.sock) to stay within SUN_LEN (~104 bytes). Tests use short target/test-runs/sp-<pid>-<n>/ run dirs.
  5. Cargo.lock. Modified only for the new intra-workspace dependency edges (agalma-sandbox -> agalma-ipc; agalma-sandbox moved from agalma-harness-opencode's normal deps to dev-deps). No external crate was added.

Consumer-invariance proof

crates/agalma-conductor/src/phases.rs changes are limited to construction sites: run_live/run_verifier_session build the harness through open_opencode_harness, and run_reference builds it through open_reference_harness (transport-aware). The shared drive/drive_reference helpers take the harness behind the contract trait (&mut LiveHarness / &mut dyn HarnessApi); phase dispatch, phase ordering, recovery, and every activity body are unchanged. build_probe and the one-shot verify runs are unchanged.

IPCX.3 — sandbox boundary on the Connect transport

Bead: agalma-ebg.4. Design: docs/ipc-connect-design.md (D1–D7). Foundation: agalma-ebg.2 (ipc.proto, Connect stack + pins, UDS accept loop, client core, Connect-level conformance harness). Depends on agalma-ebg.3 (IPCX.2 harness boundary, the migration pattern). HEAD at start: e76fbca.

Goal: move the already-extracted SandboxApi process boundary onto the Connect transport (IPCX D7, boundary #2) without changing the envelope semantics or any consumer logic, and prove it with the B1 recipe — dual-binding parity, staged rebind, rollback, IPC conformance — extended to the Connect wire. As in IPCX.2, the per-boundary evidence named by D4 (docs/ipcx-<boundary>-evidence.md) is folded into this file so the sandbox boundary's B1 and IPCX evidence stay together.

What migrated

The typed sandbox client and its method-registration helper stay the entry points; only the byte transport under them changed.

ConcernWhere
SandboxClient speaks either wire (connect_wire); connect stays framedcrates/agalma-ipc/src/sandbox_client.rs
serve_sandbox(server, socket, wire) sandbox serve entry pointcrates/agalma-ipc/src/sandbox_server.rs
Sandbox server serves the selected wire (serve reads AGALMA_IPC_WIRE)crates/agalma-sandbox/src/server.rs
SandboxProcess selects the wire, exports it to the child, connects matching clientcrates/agalma-conductor/src/sandbox_process.rs
  • The sandbox process wire defaults to Connect (sandbox_wire()); a parity run sets AGALMA_IPC_WIRE=framed to compare the two against the same scenario. The selected wire is exported to the child in the same variable, so the server serves the matching transport. Both wires announce the identical READY {json} line, so the supervisor handshake is unchanged; SandboxApi has no binding gate (Describe-free), so there is nothing else to keep wire-agnostic.
  • Envelope semantics are preserved verbatim on both wires: v/id/method/ params_json; duplicate-id receipt replay; UnknownOutcome/contract errors in-band; version refusal; unknown-method UnsupportedCapability. The Connect path reuses Server::dispatch, so no envelope code was forked.
  • No new dependency. connectrpc/buffa stay confined to agalma-ipc (architecture test unchanged and green); no Cargo.toml/Cargo.lock change.

New interfaces

  • agalma_ipc: sandbox_client::SandboxClient::connect_wire (framed connect/ from_client retained); sandbox_server::serve_sandbox.
  • agalma_sandbox::server: serve_wire; serve now reads AGALMA_IPC_WIRE (connect default, framed optional).
  • agalma_conductor::sandbox_process: sandbox_wire, SandboxProcess::wire, SandboxProcess::spawn_with_spec_wire(.., wire, ..) (spawn/spawn_with_spec retained, defaulting to sandbox_wire).

Deviations and notes

  1. The IPCX design D4 names a per-boundary docs/ipcx-<boundary>-evidence.md; this bead's scope extends the existing B1 sandbox evidence instead, keeping the framed and Connect proofs side by side (matching IPCX.2's choice).
  2. The sandbox process wire defaults to Connect. SandboxApi is Describe-free, so the "staged rebind" remains a supervised-server swap (B1.3 note 2), now over the Connect wire.
  3. SandboxProcess::spawn/spawn_with_spec keep their signatures (defaulting to sandbox_wire()), so the shared-boundary startup-cleanup test in tests/harness_process.rs (SandboxProcess::spawn_with_spec, which never reaches serve) is unchanged; spawn_with_spec_wire is the explicit-wire entry point the sandbox parity test uses.
  4. serve_wire installs a multithread Tokio runtime for both wires (the framed branch runs the serial accept loop under block_on), so sandbox methods that create processes through tokio::process keep working on both.
