Watchdog and provider-health findings (H1)

  • Detection latency. The idle watchdog fired 7× at idle_ms 120 160–120 416 (mean ≈120 239 ms) and wall_ms 120 182–120 439 ms, i.e. ~120.2 s — versus the M1.8 blind 600 s deadline. That is the ≈5× detection improvement; it is the single biggest driver of the wall-time collapse (stall cost fell from ≈80 min to ≈14 min).
  • Progress fingerprint. Every stalled session had zero token/step delta (tokens=0), so the fingerprint never advanced and the watchdog correctly classified them stalled/idle. provider_health records carried {model, binding, attempt, reason:idle, idle_ms, tokens:0, wall_ms} per H1.
  • Stall verdict path. A stalled verdict is treated as a failed attempt: it skips verify and drives retry.escalate directly (7 recorded decisions: retry on attempt 1, park on attempt 2), matching the H1 design. In M1.8 a 600 s timeout instead advanced to verify, producing empty/zero-token verify attempts.
  • Session-gone fast-fail. Not exercised this batch: every cancellation returned SessionNotFound (404) after the idle verdict, not as the terminal poll error. The fast-fail path remains covered by watchdog.rs tests.
  • Recovery by retry. One stall was escaped: rxb attempt 1 stalled at 120.3 s, attempt 2 produced the diff and merged. Retry can still recover a stalled free-tier session.

Provider health (H3 routing vs free tier)

  • All 7 stalls were opencode/big-pickle sessions that produced zero tokens in 120 s; only 1 of 8 sessions (13%) produced tokens. M1.8's free opencode/mimo-v2.6-flash-free produced 2 productive of 10 sessions (20%).
  • Routing v1 therefore did not improve free-tier provider health: the free candidate set is still stall-dominated, and big-pickle was at least as flaky as mimo-v2.6-flash-free in this environment. The success regression (25% vs 50%) tracks this flakiness, not loop mechanics — the conductor's stall→retry→park handling was correct throughout.
  • Follow-up (not this bead): validate/alternate the free builder candidate, or enable a paid tier behind the auth proxy, before trusting batch throughput.

Model routing v1 findings (H3)

  • 8 route.model decisions recorded (builder + verifier per task), all origin=static, class builder/verifier, family fix/feature, chosen free opencode/big-pickle. Paid candidates were skipped (AGALMA_ALLOW_PAID unset → eligible(..., false)).
  • Routes surfaced in the digest (route=builder:fix / builder:feature) and in each usage event; attempt model pinned as opencode/big-pickle.
  • No --model/AGALMA_MODEL override was set, so routing defaulted builders to the free coder as designed; the verifier free fallback is the same coder.

Park projection findings (H1)

  • 3 parks projected to bd status blocked + label parked + reason comment (not in_progress), and the digest/phase comments ride the issue.
  • No postmortem.md artifact was written for the stall-parks: the stall → retry → park path bypasses write_postmortem, which runs only when a red verify exhausts max_attempts. Reason/digest evidence is still on the bd issue and in the ledger, but the structured artifact M1.8 produced is absent on the stall path (observability gap).

Deviations / open items

  1. Success rate fell (25% vs 50%) despite the wall-time win. Model/provider flakiness dominated: 7/8 free sessions stalled with zero tokens. The H1–H3 mechanics behaved as designed; the free tier is the bottleneck. This is reported honestly rather than trimmed.
  2. Digest under-reports stall-then-success attempts. rxb's digest shows attempts=0 and empty commands because collect_commands stops at the first missing verify@{attempt} receipt (attempt 1 stalled, so there is no verify@1), even though verify ran at attempt 2 and the accept@2-* artifacts exist. Same for all stall-parks (attempts=0). Measurement gap in the digest, not a correctness bug.
  3. Stall-parks write no postmortem.md (see above).
  4. Working tree stale after integrate (pre-existing). After a merge, main HEAD carries the change but the origin index/worktree still hold the pre-merge content (e.g. M/D entries). This is not an H regression: the M1.8 clone shows the same (D docs/task-authoring.md). Merged-task acceptance was therefore verified against HEAD (restoring the worktree to 6ffa450), where all commands pass.
  5. bd init side effect in the clone. The isolated init created .claude/, AGENTS.md, and a bd init commit in the scratch clone (no live effect). Live repo/bd untouched.
  6. Timebox met (16.3 min < 60 min); no partial-run interruption needed.

M1.6 — stall fix batch evidence (agalma-csw.3)

Bead: agalma-csw.3 (S1 fix). Epic: agalma-csw (M1.6). Base HEAD: 69001ab (S1 root-cause, agalma-csw.1). Date: 2026-10-10. This section is appended; the H4 evidence above is unchanged.

The S1 spike (docs/spikes/stall-root-cause.md) proved the free-route "stall" was an adapter projection gap: sessions progressed (tokens, tool steps) while the harness surfaced no events until terminal, so progress_fingerprint stayed constant and the idle watchdog false-classified live turns as idle. The batch's SessionNotFoundError was a second artifact: close_session (DELETE) ran before the stall arm's cancel_operation (interrupt).

What changed

  1. Live progress surfacing (adapter). translate::events_from now emits a best-effort partial UsageSnapshot from the running session projection's live token counters (populated on each completed step), and read_events also translates the live GET /api/session/{id}/message page into a ToolOutcome per terminal tool part (completed→ok, error→err). Terminal behavior is unchanged (Completed/Failed still emit full usage + terminal event).
  2. Fingerprint advances with those deltas. progress_fingerprint already sums token deltas and steps = read_events().len(), so the new partial snapshot and per-tool events make it move mid-turn.
  3. Cancel ordering. settle_after_poll cancels (cancel_operation) before close_session for Stalled/TimedOut in the build, reference, and verifier paths; the adapter's cancel_ack_from_response treats a 404 as "already gone" (Ok, unacknowledged), so our own close can never surface a false SessionNotFoundError.
  4. Watchdog semantics preserved. With real progress signals, 120 s idle is a genuine stall; no threshold changed.

Environment

  • Fresh scratch clone (git clone --no-hardlinks of the live tree at 69001ab) into target/test-runs/hardening-batch/run-2/target, isolated bd store (bd init, prefix agalma). The conductor ran from the live working tree (with the uncommitted agalma-csw.3 changes); the scratch clone is only the workspace/origin under test.
  • Same four seed tasks and exact wording as M1.8/H4 (bodies copied byte-for-byte from the H4 tasks/t{1..4}.md). New ids: agalma-6me=seed-task-1 (README, fix), agalma-85l=seed-task-3 (builder.md, fix), agalma-s08=seed-task-2 (task-authoring.md, feature), agalma-tvz=seed-task-4 (conventions.md, feature).
  • Command (no --model; routing v1 free default; AGALMA_ALLOW_PAID unset → free route, paid credential present but gated off):
  cargo run --offline -p agalma-conductor -- work \
    --repo <clone> --max-tasks 4 --state-dir <clone>/state
  • Batch wall: 2026-10-10T13:49:12Z → 14:01:49Z = 757 s (12.6 min) (EXIT=0), inside the 60-minute timebox.

Findings

  • The projection gap is fixed. Tokens and tool deltas now reach the watchdog mid-turn. The single stall (agalma-tvz attempt 1) recorded tokens: 9 239 on its provider_health event — versus tokens: 0 for every H4 stall — and its wall_ms (232.8 s) exceeds the idle bound (120.1 s), i.e. the watchdog saw ~112 s of real progress before firing on a genuinely quiet window. Attempt 2 recovered to green.
  • The 404 is gone. The close_session-before-cancel_operation ordering produced six interrupt -> 404 SessionNotFoundError lines in H4 and zero here; cancel_operation now runs against a live session.
  • Free-tier tasks complete. Three of four tasks finished on the first attempt; the fourth needed one retry after a real 120 s quiet window. The false-stall cascade that parked 3/4 tasks in H4 did not recur.
  • Known limitation (step granularity). Liveness is emitted on step/tool completion (projection tokens, message tool parts). A single tool step that runs without completing for >120 s still reads as idle; agalma-tvz attempt 1 is consistent with that boundary. This is a genuine idle by the watchdog's definition and recovered by retry, so no threshold change was made.

Deviations / open items
