IPCX exit evidence — ConnectRPC transport for nano services

Bead: agalma-ebg.9 (IPCX.8). Epic: agalma-ebg (IPC v2). Date: 2026-10-12. Design: docs/ipc-connect-design.md (agalma-ebg.1, commit ca172d2). B1 recipe: docs/b1-extraction.md (its D1 superseded for transport only). Foundation: agalma-ebg.2 (commit 79e3b42). HEAD at exit: ca64d9e.

Epic exit criteria (agalma-ebg description): swap the cross-process nano-service transport from custom framed JSON to ConnectRPC over Unix domain sockets, envelope-first — agalma-contracts serde JSON schemas and the ledger's persisted JSON stay unchanged; all six Tier-1 seams migrate with the B1 evidence recipe (dual-binding parity, staged rebind, rollback); the agalma-www head-of-line issue is resolved; no consumer-code diff beyond construction sites.

Component map — every Tier-1 seam on the Connect envelope

The byte transport under every already-extracted process boundary is now ConnectRPC (Connect protocol, HTTP/2 over a Unix domain socket) with the frozen IpcRequest/IpcResponse/IpcError envelope (crates/agalma-ipc/proto/ipc.proto). Envelope semantics are unchanged: v, id, method, params_json; duplicate-id receipt replay; in-band ContractError codes; UnknownOutcome; version refusal; unknown-method UnsupportedCapability. The in-process bindings are untouched.

Each boundary reads the wire it serves from the shared selector Wire::from_env(Wire::Connect) — the env var is AGALMA_IPC_WIRE (connect default, framed restores the B1 length-prefixed transport for parity runs). This is distinct from the B1 binding selector AGALMA_*_TRANSPORT (in-process default, process optional), which chooses in-process vs process, not the wire under a process binding.

Consumer invariance

  • crates/agalma-contracts/** is unchanged across the epic: no schema, ID, trait, or error change (each boundary evidence doc carries its git diff --name-only proof).
  • Conductor changes are construction-site/wiring only: private wire selection, spawn_with_spec_wires, client construction. Phase/activity logic is unchanged during IPCX. Subsequent agalma-ud1 and agalma-fez work makes the Connect process transport the default for harness, ledger, workspace and task queue; sandbox already uses a process. See docs/b1-f3-evidence.md §§5–6.
  • Envelope semantics are preserved verbatim — the Connect path reuses Server::dispatch; no envelope code was forked.

Residual risks and deviations

  1. Hand-rolled proto reader (foundation deviation, tracked in docs/m0-dependencies.md). connectrpc-build shells out to protoc/buf; neither exists offline and neither may be downloaded, so crates/agalma-ipc/build.rs reads ipc.proto with a small in-repo proto3 reader and hands the codegen a FileDescriptorSet. ipc.proto stays the source of truth; codegen runs at build time; builds stay offline.
  2. Stream RPC reserved, not generated. The envelope proto carries only rpc Call(...); server streaming for future event push is reserved in a comment. No Tier-1 seam needs streaming for parity. The hand-rolled proto reader does not yet parse stream modifiers, so adding the reserved RPC later needs a reader extension.
  3. hyper-util accept loop. connectrpc 0.9.1 has no public Server::serve_connection; the UDS accept loop uses hyper_util::server::conn::auto::Builder::serve_connection, one task per accepted connection (crates/agalma-ipc/src/connect.rs::serve). This is the documented UDS path and supplies the HTTP/2 multiplexing that closes agalma-www.
  4. Nested block_on fix (agalma-ebg.8). The kernel server both serves over Connect and calls its LedgerClient synchronously from inside the async Connect handler; the framed client was synchronous so this was latent, but over Connect Runtime::block_on panics ("cannot start a runtime from within a runtime"). agalma_ipc::block_on_nested (tokio::task::block_in_place) steps the worker aside so the peer reactor progresses; ledger_client::call uses it, and the execution client applies it defensively. Other Connect clients are not nested today and were left untouched.
  5. Execution default still deferred. Harness's default process flip is live proven by agalma-ud1; ledger, workspace and task queue switch to process in agalma-fez, with bounded production sockets and local server smokes. Sandbox is always process. Process bindings default to Connect, with framed wire and in-process transport overrides retained. Execution/kernel remains in-process by default until production selection/integration in CV.1 (agalma-pob.1). See docs/b1-f3-evidence.md §§5–6.
  6. ExecutionApi adapter gap resolved, not residual. The agalma-5de B1-F1 gap (step/recover returning UnsupportedCapability over the process boundary) is closed by caller-side effect dispatch (commit 6e8d69a); IPCX.7 proves step/recover and the handler-registry protocol faithful over both wires at the engine-op level.
  7. Test-only lint nit. cargo build --offline --workspace is warning-free; the harness_connect test target emits one unused-import warning (ServerInfo). Out of this bead's scope (docs + architecture tests only); harmless.

Verdict

All six Tier-1 seams — harness, sandbox, workspace, task queue, ledger, and the execution/kernel boundary — speak the ConnectRPC envelope over UDS with full B1-recipe evidence (dual-binding parity, staged rebind, rollback) recorded in the per-boundary docs above. The agalma-www head-of-line constraint is gone (HTTP/2 multiplexing), contracts and the ledger at-rest JSON are unchanged, and the Connect stack is confined to agalma-ipc at the manifest and source levels (9 architecture tests green). Builds are offline (cargo fetch --offline empty; cargo build --offline --workspace clean). Residual items are tracked (agalma-pob.1 production kernel integration; the reserved Stream RPC for TUI push). Epic agalma-ebg closes on this record.
