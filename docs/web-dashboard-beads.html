Parallel ownership

  • A: WEB.2 read service/economics/routing, WEB.9 typed contracts, WEB.11 adapters. Contract and summary can occupy independent available implementers initially; the three-stream limit is an active-work budget, not a static model assignment.
  • B: WEB.10 work.rs/CLI/work::factory_runtime and composition after WEB.2. Declaring the runtime submodule from work.rs avoids a concurrent lib.rs edit.
  • C: WEB.4 Cargo/package/server/build; then WEB.6 assets/page/browser support. WEB.4 health.html is separate from WEB.6 index/app. Asset additions need no server/inventory edit.
  • IPC: finish WEB.3 review, then WEB.12 receives those files and uses a free implementation slot. Factory clients use WEB.9 fixtures before live services.
  • Join: composition transfers WEB.2→WEB.10→WEB.13; package server WEB.4→WEB.13. WEB.11 never owns composition. Browser support begins WEB.6 and is reused by later tests rather than replaced.

At most three active implementation sessions and two isolated test binaries by default. Use named worktrees/branches and absolute redirected cache paths; coordinate compilation/ports/state/browser profiles. A missing predecessor goes back to its owner, not an unbounded cross-task repair. This is a manual dispatch cap.
