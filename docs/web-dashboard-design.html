This replaces the first-delivery sequence accepted on 2026-10-13. Implementation remains paused; this planning update does not resume dispatch, spend, or resolve execution gates.

Product and delivery

One operator starts a local factory for one repository/state directory, opens its printed loopback URL, sees the eligible queue and execution progress, and leaves workers consuming eligible work automatically. The cockpit remains available through an empty queue, long tasks and admission pause. Pause/resume controls use existing factory authority and durable receipts. High-level planning through concierge is a later increment; there is no per-task Dispatch button.

Two milestones keep a visible page ahead of runtime integration:

MilestoneObservable resultAcceptance owner
M1: open the cockpitActual browser shows real overview/executions/component health through the production hostWEB.6
M2: operate the queueContinuous automatic eligible-work consumption, responsive busy/idle UI, verified pause/resume and restart recoveryWEB.13

The first page also shows available economics/timeline and eligible work/runtime observations when supported. Unknown costs, worker state and source availability remain explicit. M1 may show the factory runtime endpoint unavailable with controls disabled; this is an intermediate delivery, not M2 acceptance.

Remote access, shared accounts, a frontend framework/npm pipeline, task/backlog editing, arbitrary commands, per-task worker/model selection, rich plugin-detail pages, artifact downloads, generic plugin actions and concierge UI are outside the first release. Existing queue eligibility/approval/stop/spending policies remain mandatory. Automatic queue consumption does not create/release new tasks.

Package and process boundary

Retain agalma-web-dashboard as an independently installed/supervised process. Its package supplies executable, manifest, configuration schema, protocol version and committed browser assets. Use public contracts and IPC only. Discover and launch through the existing registry/supervisor; no dashboard-specific core import, peer discovery, second supervisor, SQL or private ledger open.

Rust serves compiled HTML/CSS/browser JavaScript modules and bounded HTTP API. WEB.4 generates a deterministic inventory using std-only build logic; adding an asset does not require editing server source. Watch source assets, never an OUT_DIR output. WEB.4 owns Cargo/package/build/server and distinct health.html; WEB.6 owns final page/modules/browser support. No new dependency/download is authorized. A build-script change includes existing no-op rebuild verification.

Bind 127.0.0.1, default port 0; reject foreign addresses. Print/report actual URL only after listener/read binding readiness. Configuration refresh interval is 1–60 seconds, default 1. Health distinguishes listener, binding and runtime availability. Missing optional runtime support does not make M1 startup fail.

Continuous runtime and ownership

Add explicit agalma work --watch --repo <repo> --state-dir <state> --plugin-root <packages>. Reject --watch with --once or --max-tasks. Existing ordinary batch/once/max-tasks behavior and exit codes remain covered.

One runtime holds the existing state-directory admission lock. One worker owns queue selection, claim, frozen admission and serial execution. Empty successful queue means Idle and an interruptible five-second wait; later eligible work runs through the existing pipeline. Queue error means Unavailable with capped retry (5 seconds initial, 30 seconds maximum), never successful empty state.

On admitted startup, run existing frozen-package recovery before new claims, then existing reap/reconciliation/review policy in its established order. Do not repeat startup recovery/planning on every idle scan or add automatic release, mining, recurring concierge or a parallel builder scheduler. M3's durable cadence, operator-directive release, backup and 72-hour acceptance remain separate work.

Three responsibilities progress independently:

  1. The worker runs synchronous task execution and is the sole claimant.
  2. A host/probe supervision owner is constructed/used in its own context and continues supervision during idle, running and paused states (nominal 250ms tick with existing backoff). Share only safe selected-ledger/router/report handles and short-lived snapshot copies; never mutable host/queue/executor.
  3. The hub callback/control event loop remains responsive while the worker blocks. The supervised dashboard process separately serves browser HTTP. A supervision thread alone is insufficient. Never hold a worker/router lock throughout a task or slow read. Wake hints use a bounded channel (capacity16); coalescing a hint never drops the durable stop decision.

Pause blocks new admission through existing stop policy; it is not a new cancel operation and does not change current in-flight phase-stop semantics. Resume requires the existing human confirmation and receipt. Wake/recheck actual stop state instead of treating a successful HTTP response as observed worker state.

Continuous-mode startup with STOP/latch may serve observations and confirmed resume only against readable, compatible established storage. Never initialize, replace or migrate fresh/missing/corrupt state under stopped admission, clear stop automatically, or dispatch while recovery/stop authority is unknown. This is an explicit continuous-mode change, not behavior already in work().

Graceful shutdown stops admission, uses existing cooperative phase/cancellation deadlines to reach a terminal/parked boundary, then stops/joins hub serving and host owners, drains owned plugin processes, and finally releases the lock. Forced termination can leave durable nonterminal execution; next permitted startup recovers from frozen packages before new work. No fabricated terminal receipt or force-unlock. Fatal worker failure is visible and requires explicit runtime restart; plugin-child restart does not create a fresh queue claimant.

Summary reads

Keep immutable WEB.1 ControlPlaneRead/v1 / BrowserWire and scoped control-plane.read/v1. Supported first-release operations are read_overview and list_components, exposed as GET /api/v1/overview and GET /api/v1/components. Grant scope/expiry/revocation remain server-validated.

ReadOverview contains stop observation, executions, usage/cost/allowance and curated timeline from bound APIs. Sources distinguish missing, unreadable, unknown, successfully empty and available. Unknown usage/allowance is null, not numeric zero. Missing stop authority cannot become a green Running indication. No implicit atomic snapshot is claimed across sources.

Overview is capped at100 executions/100 timeline entries and256KiB actual wire JSON with visible truncation. Component pages default50, accept1–100, and stay within256KiB including metadata. Sort by opaque ID; cursor pins collection, filter and revision. Mutation/retired generation invalidates the collection; RevisionConflict means reacquire. Fingerprint revisions are not monotonic clocks.

Use installed binding/version/config pins plus live host lifecycle/health. An old Ready report cannot hide a Failed/Retired registry observation. Include installed unavailable plugins. Do not derive liveness from socket presence. Preserve exact decimal strings for identity/money in browser projection.

Keep reads available while admission stopped, bounded by five seconds including queueing/source work, and release router locks before slow I/O. Reads create no claims/actions. Component-report/artifact operations explicitly unsupported in this slice; their HTTP routes are absent. Preserve their old code/tests/evidence before editing the retained WEB.2 worktree. Timestamp/digest matching never establishes missing producer provenance.

Factory contracts

WEB.9 defines additive factory.rs types, strict codecs and independent golden fixtures. Existing ControlPlaneRead/v1, HP envelopes and LedgerApi are unchanged. Capabilities separate factory.read/v1 (snapshot/lookup) from factory.control/v1 (pause/resume). No public body contains actor or credentials.

Requests use exact tags/fields; unknown fields/families/versions fail:

{"format":"FactoryRuntime/v1","operation":"snapshot","limit":50,"cursor":null}
{"format":"FactoryControl/v1","operation":"lookup","action_id":"op-1"}
{"format":"FactoryControl/v1","operation":"pause","action_id":"op-2","confirmation":null}
{"format":"FactoryControl/v1","operation":"resume","action_id":"op-3","confirmation":"resume"}

Snapshot limit defaults50/accepts1–100; nullable cursor≤4096 UTF-8 bytes. Omitted snapshot paging fields take defaults. Action IDs are1–128 ASCII characters from [A-Za-z0-9._-]; action confirmation is required nullable and≤64 UTF-8 bytes. Preserve exact submitted confirmation for input identity, then apply existing trimmed confirmation semantics. Request digest is canonical SHA-256 over the complete validated action object, excluding outer grant/deadline/operationID, session and CSRF. Distinct submitted input with the same actionID conflicts.

WEB.10 owns queue order/revision/cursor/source truth; WEB.11 only validates and adapts it. Queue cursor is canonical JSON text, opaque to browsers: {format:"FactoryQueueCursor/v1",repository_id,state_id,runtime_instance_id, revision,after}. Fields are bounded/nonempty and pin scope/launch/collection. Malformed/wrong scope returns InvalidRecord; changed queue revision/launch returns RevisionConflict. Golden literals freeze encoding. WEB.10's raw source permissions default false. WEB.13 supplies the live binding/owner resolver. WEB.12 and the browser can only narrow this result. UI permissions are hints, never admission authority.

FactoryControl/v1 responses are strict tagged variants, all with nullable live observed_stop separate from immutable history:

  • result:"receipt", receipt:{action_id,request,request_digest,outcome, reason,ledger_action_id,actor,recorded_at_unix_ms}. Outcome applied/denied, actor human, timestamp exact, nullable reason≤2048bytes.
  • result:"unconfirmed", original action_id/request/request_digest, code:"EffectUnconfirmed", bounded reason; no terminal receipt.
  • result:"not_found", action_id. Only authoritative lookup can say absent.

Whole response≤256KiB. Reuse existing FailureCode values; no frozen failure enum extension for HTTP-only session/content errors. A completed historical timestamp is replayed exactly. Receipt success and observed worker progress are distinct.

Control replay, stop admission and authority

Existing ControlPlane::apply changes latch/STOP before recording an outcome; it does not preserve complete original request identity or atomically commit all effects. The new API promises conservative replay, not atomic exactly-once completion. Preserve legacy CLI/TUI apply/cancel behavior.

One serialized API control owner holds a dedicated state-scoped factory-control.lock guard; a process mutex alone is insufficient. WEB.13 establishes ownership for the service lifetime. Unbound/competing owner means disabled controls. Legacy CLI/TUI never uses this API's reserved action IDs.

Use existing declared ControlReceipt storage, with deterministic IDs factory-control.intent/<action_id> and factory-control.result/<action_id>. Fields use action pause/resume, target empty, actor human, and a namespaced factory_control_v1 detail with stage, exact request and digest; terminal detail adds actual outcome/reason. No SQL or parallel journal framework.

  1. Authenticate method/capability/pinned identity/expiry and strictly decode.
  2. Serialize at exclusive owner; recheck deadline/authority after waiting.
  3. Matching completed record replays exactly; conflicting input fails before effects. Matching orphan intent returns unconfirmed without reexecution.
  4. Otherwise persist intent before effect; uncertain intent write never authorizes effect. Reconcile or return explicit unavailable/unknown.
  5. Apply existing human guards/checked pause/resume semantics, then persist and return terminal result. A mutation/result-write failure leaves uncertainty. New-path Resume must not claim success if STOP removal/observation failed.

Lookup is observational. An interrupted effect/result boundary returns EffectUnconfirmed; browser does not retry with another ID automatically. A stronger atomic guarantee requires a separate ledger prerequisite.

Pause/resume must be callable while admission stopped. Add a narrow authenticated factory-control exception after operation validation; do not disable ordinary effect stop policy or admit arbitrary plugin capabilities. Missing/unreadable state still fails closed. Read/lookup remains observational while stopped.

Control authority is explicit for the installed dashboard binding/package digest, not inherited from auto-install, a UI actor field or plugin report. Do not add factory.control/v1 to the automatic safe-capability allowlist. Default package is read-only. Live grant expiry/revocation/generation still gates every call.

Browser state and refresh

Use one page and browser-native modules. api.js validates contracts; app.js renders the shell; refresh.js owns reads; controls.js owns explicit pause/resume interactions. Independent WEB.9 JSON fixtures let UI and backend develop in parallel. No private implementation imports or remote UI dependencies.

One refresh cycle at a time, default1s/config1–60s, abortable5s requests. Track last success per source; one failing endpoint does not erase successful others. Retain failed-source data visibly stale; first failure is unavailable. Generation change replaces old current row state. RevisionConflict resets page collection; older aborted replies cannot overwrite later cycles. Page exit stops timers and requests. Opaque identities/revisions/money never become floating point.

Use textContent/createTextNode for plugin text. Bound text4KiB, rows100/page, explicit truncation/Next. Never evaluate report HTML/scripts/templates. Controls disabled when runtime/permission unknown or absent. Explicit Resume collects literal existing confirmation. Pending click retains one actionID; lost result queries it. GET/refresh/navigation/reconnect/reload never repeats POST.
